API ​

Construction ​

TreeArrays.TreeArray Type
julia
TreeArray

Dispatch alias for a TreeData backed by an AbstractArray, including ragged trees at their outer level. Basic array operations forward to the backing: size, length, ndims, axes, eltype, indexing, iteration, collect, and Array. TreeData itself is not an AbstractArray subtype; use TreeActualArray for a numeric array view.

source
TreeArrays.TreeData Type
julia
TreeData(backing, dims...; kwarg_dims...)
TreeData(name => namedtuple, dims...)

Wrap backing storage with named dimensions, without copying it. Positional symbols or name => coordinates pairs describe physical axes in storage order. Keyword arguments describe fixed metadata. The backing can be a numeric array, a record, an array of trees, a tuple, or a scalar.

The pair form names a record axis; its fields become table columns and can be read with property access. Raw fields inherit the record's inner dimensions; fields already wrapped in TreeData retain their own dimensions. An array of trees represents ragged nesting. Siblings must share layout and compatible numeric element types, but their lengths may differ.

Use parent(X) to obtain the original backing. The four layout aliases below are for dispatch; construct through TreeData. An array or tuple of plain named tuples is rejected: use field arrays or wrap each record as a tree. Calling TreeData with dimension names and no backing is an error.

source
TreeArrays.TreeDim Type
julia
TreeDim(name::Symbol, values)
TreeDim(name::Symbol)
TreeDim(name => values)

A named dimension of a TreeData. A tuple, vector, or range supplies coordinates; the one-argument form creates an unlabelled array axis. Coordinates are retained as provided. A scalar denotes fixed metadata; nothing denotes a reduced dimension. Fixed and reduced dimensions add no physical array axis. Use coords to read the coordinates of a labelled axis.

source
TreeArrays.TreeNamedTuple Type
julia
TreeNamedTuple

Dispatch alias for a TreeData backed by a named tuple. Construct with TreeData(name => fields, dims...) to name the record axis. Read fields with X.field and the record axis with outerdim.

TreeArrays.TreeRaggedArray Type
julia
TreeRaggedArray

Dispatch alias for a TreeData backed by an array of trees. Array operations describe the outer array; inner reductions operate within each child. Outer reductions require matching kept axes or an explicit alignment policy. See mapslices.

TreeTuple

Dispatch alias for a TreeData backed by a tuple, such as the output of a quantile reduction with tuple-valued levels.

TreeArrays.dims Function
julia
dims(X::TreeData)
dims(A::TreeActualArray)

Return the dimensions declared on this node in declaration order, including fixed and reduced dimensions. This does not recursively collect dimensions from children. Use coords for a labelled axis's coordinates. Inside functions with a dims keyword, qualify the call as TreeArrays.dims(X).

TreeArrays.outerdim Function
julia
outerdim(X::TreeNamedTuple)

Return the record axis whose coordinates are the field names. The record must have been built with the named pair form of TreeData; a raw named-tuple backing without a named record axis does not supply one.

source
TreeArrays.coords Function
julia
coords(d::TreeDim)
coords(X::TreeData, name::Symbol)

Return a labelled axis's coordinates in their original container type. The named form searches this node, not its descendants. For an axis within a ragged tree, read the appropriate child first.

An unlabelled, fixed, reduced, or absent dimension raises an error. collect(d) is dimension iteration, not coordinate access. Within a slice kernel, request coordinates with mapslices(...; coords=true).

Statistics.mean Method
julia
mean(X::TreeData; dims=nothing, threads=true, align=nothing)

Mean over named dimensions, using mapslices. With dims=nothing, delegate to mean(parent(X)); this is a scalar mean for numeric array backing, not a recursive mean over arbitrary records. threads=false disables parallel slice evaluation. align selects a ragged coordinate policy.

source
Statistics.quantile Method
julia
quantile(X::TreeData, probabilities::TreeDim; dims, threads=true, align=nothing)
quantile(X::TreeData, probabilities::NamedTuple; dims, threads=true, align=nothing)
quantile(X::TreeData, name => probabilities::NamedTuple; dims, threads=true, align=nothing)

Compute the requested quantile levels together for each slice. A TreeDim creates a probability axis; its coordinate container is preserved. A scalar probability in a TreeDim creates fixed metadata rather than a varying axis. A named tuple creates a record. A name paired with a named tuple creates an axis labelled by the tuple's keys, with probabilities taken from its values.

Each slice is copied into reusable scratch storage before sorting; inputs are not sorted in place. NaN raises an error. Load NaNStatistics for nanquantile with the same forms; it drops NaNs per slice and returns NaN for an empty valid slice. Threading and ragged alignment follow mapslices, with threading enabled by default here.

Statistics.var Method
julia
var(X::TreeData; dims=nothing, corrected=true, threads=true, align=nothing)

Variance over named dimensions. corrected=true uses the sample denominator; false uses the population denominator. Pool multiple sample dimensions in one call rather than composing variances. A precomputed mean keyword is not supported. With dims=nothing, delegate to var(parent(X); corrected). Threading and alignment follow mean.

source
TreeArrays.hdi Function
julia
hdi(y::AbstractVector, mass=0.9)
hdi(X::TreeData; dims, mass=0.9, threads=true, align=nothing)

Return the shortest sample interval containing at least mass of the draws, as (lower, upper) named fields. Endpoints are observed draws; tied widths choose the lowest interval. mass must be in (0, 1]. Empty or NaN-containing samples raise errors. A single interval can span a gap in multimodal samples.

The tree method returns a record per slice through mapslices. It uses scratch storage for sorting and does not mutate the input.

source
Base.mapslices Method
julia
mapslices(f, X::TreeData; dims, coords=false, threads=false, align=nothing)

Apply f to each slice along the named dimensions and return a TreeData. dims is a symbol or a collection of symbols. The function returns a scalar (to collapse the dimensions) or a tree (to introduce an output axis or record). Wrap a named-tuple result with TreeData(name => result). Reduced dimensions remain in metadata but no longer contribute array axes.

For one labelled dimension, coords=true passes its coordinate vector as a second argument to f. An unlabelled dimension cannot supply coordinates.

Inner reductions visit each ragged leaf independently. An outer reduction requires compatible kept axes. align=:union matches every coordinate present in any leaf, using only available contributors; align=:intersect retains coordinates present in all leaves. Neither interpolates. Pooling outer and inner dimensions together requires array-backed leaves and reduction of all outer axes; select a record field before pooling.

threads=true permits concurrent evaluation of independent slices. Kernels must be thread-safe and must not mutate input slices. Threaded reducers may retain scratch buffers per task. A missing dimension raises an error.

source
TreeArrays.@kernel Macro
julia
@kernel (:reduces => :into) function f(slice) ... end
@kernel (:reduces => :into) function f(slice, coords) ... end
@kernel (:reduces => :into) [coords=true] f

Add a tree method to a slice function. The defining form keeps the plain-array method and generates a TreeData method that reduces :reduces, wraps the named-tuple output as a record on :into, and delegates to mapslices. A two-argument defining form receives the reduced axis's coordinates.

The post-hoc form adds the tree method to an existing function. Specify coords=true when that function needs coordinates. Generated methods take threads=false and align=nothing keywords; opt into threading only for thread-safe functions. Use mapslices directly for a variable dimension signature or non-record output.

Selection and sweeps ​

Base.selectdim Method
julia
selectdim(X::TreeData, name => selector)
selectdim(X::TreeData, name::Symbol, selector)

Select an array axis on the current node using a view of its backing. A regular expression keeps matching coordinate strings; a predicate keeps coordinates for which it returns true. A boolean vector selects by mask, and an integer vector selects positions, possibly reordered or repeated. Positional selectors also work on unlabelled axes. A bare string selector is ambiguous and rejected.

The selected labels are retained. This applies to dense leaves and ragged outer axes, not record axes or dimensions inside ragged children. Select a record field or descend to the child first. Missing, fixed, and reduced axes raise errors.

source
Base.map Method
julia
map(f, dimension::TreeDim)
map(f, Iterators.product(dimensions::TreeDim...))

Construct a named scenario grid. A single dimension passes each coordinate to f; a product passes a coordinate tuple in dimension order. Each cell returns a scalar or a TreeData. Wrap named tuples as named records. stack accepts the same dimension-sweep forms. Sweep dimensions must have iterable coordinate collections, rather than unlabelled, fixed, or reduced metadata.

Base.getproperty Method
julia
X.field

Read a record field without copying it. A field already wrapped in TreeData is returned as stored; a raw field is wrapped with its container's inner axes. Property access on ragged records visits the leaves. propertynames(X) lists available fields. An unknown field raises an error.

Views ​

TreeArrays.TreeTable Type
julia
TreeTable(X::TreeData; wide=())

Present a tree through Tables.jl with selected axes pivoted into columns. Record fields are already wide; other varying axes contribute long coordinate columns and a value column. wide accepts a dimension name or a tuple of names. Nested column names are joined with underscores; collisions raise errors. A ragged axis cannot be pivoted wide.

Array-valued record fields must carry their own dimensions as TreeData leaves; container dimensions alone do not define the fields' table row axes. Container axes may duplicate field axes when their names and coordinates agree.

Tables.rows, Tables.columns, and Tables.schema expose the view. Numeric backing is read lazily; materialization depends on the downstream consumer. Use Tables.rowtable to collect rows. Constructing a table view does not alter the tree's layout or choose an alignment policy.

source
TreeArrays.TreeActualArray Type
julia
TreeActualArray(X::TreeData)
TreeActualArray(X::TreeRaggedArray; dims, align)

A read-only numeric AbstractArray view that retains its tree and reads through the existing backing. Dense leaves, homogeneous records, scalar terminals, and grids of homogeneous numeric scalar leaves are supported. Record axes follow the inner physical axes. Fixed and reduced dimensions remain in dims(A) but do not add array axes. parent(A) returns the tree; Array(A) copies values.

Keep shape, coordinates, and terminal types unchanged while a view exists. A view of a reduced result aliases that result, not the reducer's original input. Tuple records, mixed element types, and nested arrays of sub-trees are unsupported by the plain constructor.

For a one-level vector of array-backed ragged leaves, name both dims and align. :truncate_min selects leading positions up to the shortest length; :thin_min selects evenly spread positions; :error_equal requires equal lengths. Coordinates at the selected positions must agree across leaves. Other leaf axes must match in length and coordinates. The outer sibling axis is inserted immediately after the aligned inner axis. These policies select positions without interpolation.
